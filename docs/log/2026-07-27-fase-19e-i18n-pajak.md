## Batas penerjemahan: nama resmi vs konsep

Halaman ini paling padat istilah pajak Indonesia, jadi batasnya perlu tegas:

| Dipertahankan apa adanya | Diterjemahkan |
| --- | --- |
| PPh Final, PPh 23, SPT Masa PPN 1111, Bukti Potong, NPWP, DPP | Pajak Keluaran → Output VAT |
| | Pajak Masukan → Input VAT |
| | Omzet → Revenue, Masa → Period |

**Alasannya bukan selera.** Nama dokumen dan pungutan resmi Direktorat Jenderal
Pajak harus tetap dikenali saat pembaca mencocokkannya dengan formulir aslinya
— menerjemahkan "SPT Masa PPN 1111" justru menyulitkan. Sebaliknya "Pajak
Keluaran"/"Pajak Masukan" adalah **konsep** dengan padanan baku, dan kamus ini
memang **sudah** menerjemahkan PPN menjadi "VAT" sejak Fase 16 (`tanpaPpn`:
"Tanpa PPN" → "No VAT"). Mengikutinya menjaga konsistensi.

Untuk nama resmi yang mungkin asing bagi pembaca Inggris, keterangan
ditambahkan alih-alih diganti — mis. `tabSptPpn` → "Periodic VAT return (SPT
Masa PPN)".

## Peta label `packages/shared` (pola 16t)

`PPH23_OBJECT_LABELS` tinggal di `packages/shared` dan **tetap berbahasa
Indonesia**, karena `apps/api` ikut memakai paket itu — paket bersama tidak
boleh bergantung pada kamus web. Pemetaan kode → kunci karena itu dilakukan di
sisi web:

```ts
const PPH23_OBJECT_KEY = {
  jasa: "pph23Jasa", sewa: "pph23Sewa", royalti: "pph23Royalti",
  bunga: "pph23Bunga", dividen: "pph23Dividen",
} satisfies Record<Pph23ObjectCode, UiKey>;
```

`satisfies` di sini bukan hiasan: menambah objek PPh 23 baru di `shared` tanpa
menambah terjemahannya di sini akan **gagal saat kompilasi**, bukan tampil
sebagai teks kosong.

## Ekspor CSV tetap berbahasa Indonesia

Header kolom `downloadCsv` **tidak** diterjemahkan. Ini bukan kelalaian
melainkan **keputusan yang sudah berlaku**: `reports.tsx` sudah sepenuhnya
dwibahasa sejak Fase 16e/16n, dan header CSV-nya tetap Indonesia
(`["Kode", "Akun", "Jenis", "Jumlah"]`). Alat sapuan pun mengelompokkannya
terpisah sebagai `BERKAS`, bukan `LAYAR`.

Alasannya sejalan dengan keputusan pemilik soal dokumen cetak: berkas ekspor
ditujukan untuk akuntan dan pelaporan, bukan untuk dibaca di layar.

Konsekuensinya satu baris `PPH23_OBJECT_LABELS` **tetap diimpor** — dipakai
khusus untuk jalur CSV, sementara layar memakai peta kunci di atas. Perbedaan
itu diberi komentar di tempatnya supaya tidak terlihat seperti sisa yang
terlewat.

## Kunci kembar (lagi) dan hook per sub-komponen

- `nomor` ({ id: "Nomor", en: "Number" }) saya tambahkan padahal **sudah ada
  sejak Fase 16 dengan isi persis sama** — TS1117. Ini kejadian **ketiga**
  berturut-turut (19c: `barisKe`, 19d dicegah, 19e: `nomor`). Kompilator
  memang penjaganya, tapi polanya cukup jelas untuk dicatat: pada kamus ±680
  entri, memeriksa lebih dulu lebih murah daripada menunggu gagal.
- Berkas ini punya **empat komponen** (`PajakPage`, `PphFinalSection`,
  `Pph23Section`, `SptPpnSection`, `SptTable`) dan masing-masing butuh
  `useUi()`-nya sendiri. Menaruhnya hanya di komponen induk menghasilkan
  belasan `TS2304: Cannot find name 'u'` — gagal keras, jadi tidak mungkin
  lolos diam-diam.

## Cek baru `F1e`

Penanda negatifnya sengaja memakai **kalimat panjang** ("Setor PPh Final masa",
"Riwayat setoran PPh Final"), bukan kata "Pajak" atau "Masa". Sebabnya khas

karena memang tidak diterjemahkan — penanda negatif berbasis kata tunggal akan
merah selamanya walaupun terjemahannya benar.
